# 基于 FCN 改进 LeNet-5 的手写数字分割（MNIST 合成数据）

本项目仿照 **FCN（Fully Convolutional Network）** 的思想，把经典分类网络 **LeNet-5**
改造成**全卷积分割网络**，在「MNIST 数字 + 真实背景」合成的数据上完成手写数字分割。
按作业要求，对比了两种上采样方式（Upsampling / Deconvolution）与两种分割粒度
（前景背景 2 分类 / 按数字类别 10 分类），共 **4 个组合**。

## 目录结构

```
mnist_segmentation/
├── dataset.py        # 数据合成：前景数字 + 背景patch → 合成图 + 分割GT
├── seg_models.py     # FCN 版 LeNet-5（含 skip connection，支持两种上采样）
├── seg_engine.py     # 训练 / 评估(mIoU) / 可视化
├── main_seg.py       # 主入口：跑全部 4 个组合并汇总
├── backgrounds/      # 20 张背景图（网络下载的真实照片）
└── results/          # 产物：曲线、分割可视化、权重、汇总表
```

## 一、数据合成（预处理）

作业要求用合成数据训练。每个训练样本的生成流程（见 `dataset.py`）：

1. **前景**：从 MNIST 随机取一个数字（28×28 灰度），用**灰度阈值**（>0.3）抠出数字笔画作为前景 mask；
2. **背景**：从 20 张网络下载的真实照片中随机选一张，**随机裁一个 patch** 作为背景画布（64×64）；
3. **合成**：对数字做随机缩放（0.8~1.6 倍）、随机平移后贴到背景上，得到合成图；
4. **分割 GT**（与合成图同步生成）：
   - **2 分类**：数字像素 = 1（前景），其余 = 0（背景）；
   - **10 分类**：数字像素 = 数字类别 + 1（即 1~10），背景 = 0。
     因此 10 分类分割实际是 **11 个输出通道**：通道 0 为背景，通道 1~10 对应数字 0~9。

> 背景图来源：通过程序从公开随机图库（picsum.photos）下载 20 张真实照片，存于 `backgrounds/`。
> 合成样例可见 `results/sample_synthesis.png`。

## 二、网络结构：FCN 版 LeNet-5

核心改造（见 `seg_models.py`）：

1. **全卷积化**：去掉 LeNet-5 末端的全连接层，改用 **1×1 卷积**替代，使网络能逐像素输出类别、
   接受任意尺寸输入——这是 FCN 的基本思想。
2. **编码器**：沿用 LeNet-5 的「卷积 + tanh + 平均池化」提取特征（下采样）。
3. **解码器 + 跳跃连接**：把编码器下采样后的低分辨率特征上采样回输入分辨率。
   并仿照 **FCN-8s** 加入**跳跃连接（skip connection）**：把编码器浅层的高分辨率特征
   融合进解码器，恢复分割边界细节（实验表明这显著提升了 mIoU 与边界清晰度）。
4. **两种上采样方式**（作业要求对比）：
   - **Upsampling**：双线性插值，无参数；
   - **Deconvolution**：转置卷积 `ConvTranspose2d`，可学习参数。
     其权重用**双线性核初始化**（FCN 论文标准做法），否则多类分割上容易收敛不稳。

训练：逐像素交叉熵损失，Adam（lr=1e-3）。因背景像素占比高达 ~94%，采用**前景加权损失**
（背景类权重设为 0.3），避免网络“偷懒”把整图都判为背景。

## 三、运行方法

```bash
pip install torch torchvision numpy matplotlib pillow

python main_seg.py                      # 跑全部 4 个组合（2类 25轮，建议10类用更多轮）
python main_seg.py --only 2cls_upsample # 只跑某个组合

```

## 四、实验结果

评估指标：**mIoU**（分割标准指标，各类 IoU 的平均）与**像素准确率**。
由于背景占比极高，像素准确率会偏高（全判背景也有 ~94%），**mIoU 更能反映真实分割质量**。

| 组合 | 分割类别 | 上采样方式 | 参数量 | mIoU | 前景mIoU | 像素准确率 |
|---|---|---|---|---|---|---|
| 2cls_upsample | 2 分类 | Upsampling | 61,074 | **0.845** | 0.662 | 97.9% |
| 2cls_deconv | 2 分类 | Deconvolution | 61,206 | 0.802 | 0.626 | 97.9% |
| 10cls_upsample | 10 分类(+背景) | Upsampling | 62,055 | 0.420 | 0.363 | 97.2% |
| 10cls_deconv | 10 分类(+背景) | Deconvolution | 65,949 | 0.395 | 0.336 | 96.9% |

（2 分类训练 25 轮，10 分类训练 40 轮。各组合的分割可视化见 `results/<组合名>_pred.png`，
训练曲线见 `results/<组合名>_curves.png`。）

## 五、结论分析

1. **全卷积化 + 跳跃连接确实有效**：加入 skip connection 后，2 分类 mIoU 从初版的约 0.65
   提升到 0.80+，分割边界明显更清晰。这验证了 FCN「用浅层高分辨率特征恢复细节」的核心思想。

2. **2 分类 vs 10 分类**：2 分类（前景/背景）mIoU 高达 0.80~0.85；10 分类（还要判断具体是哪个数字）
   mIoU 降到 0.40 左右。下降是**符合预期**的——10 分类不仅要分出前景，还要在前景内部区分 0~9，
   任务难度大得多；且 11 类 mIoU 对背景 + 10 个数字类求平均，而每张图只含一个数字，
   其余类别在该图缺席，会把平均 IoU 拉低。因此两种任务的 mIoU 不宜直接横向比较。

3. **Upsampling vs Deconvolution**：两者精度接近，Upsampling 略优且参数更少（无额外可学习参数）；
   Deconvolution 参数略多、理论上更灵活，但需**双线性核初始化**才能稳定收敛——未做此初始化时
   10 分类 Deconv 的 mIoU 一度只有 0.13，加上初始化后回升到 0.40，与 Upsampling 持平。
   说明对本任务，简单的插值上采样已足够，转置卷积的额外容量并未带来明显收益。

## 六、合规优化（消融对比）

在**不改动骨干网络（仍为 LeNet-5）、不改动数据合成方式、不改动 4 组合设定**的前提下，
做了三项训练/评估层面的优化，并与基线做干净的消融对比：

1. **Dice + 交叉熵组合损失**：在前景加权交叉熵基础上加入 Dice Loss，直接优化前景重叠度，
   对“前景占比极小”的类别不均衡问题更鲁棒（`--loss dice_ce`）。
2. **更长训练 + cosine 学习率衰减**：轮数提到 50，并加入余弦退火调度，使收敛更充分平稳。
3. **补充评估口径 mIoU(出现类)**：标准 mIoU 会把每张图中缺席的 9 个数字类别也按 IoU=0 计入，
   严重低估真实能力。补充“仅对该图真值中出现过的类别计 IoU”的指标，更贴合单数字分割场景。

**基线 vs 优化 对比**（mIoU 均取训练过程中的最佳值）：

| 组合 | 基线 mIoU | 优化后 mIoU(全类) | 优化后 mIoU(出现类) | 像素准确率 |
|---|---|---|---|---|
| 2 分类 Upsampling | 0.845 | **0.867** | 0.857 | 98.7% |
| 2 分类 Deconvolution | 0.802 | **0.866** | 0.855 | 98.7% |
| 10 分类 Upsampling | 0.420 | 0.408 | **0.706** | 97.2% |
| 10 分类 Deconvolution | 0.395 | 0.415 | **0.708** | 97.2% |

**关键观察**：
- 2 分类两种上采样都提升到 0.86+，其中 Deconvolution 提升最大（0.80→0.87），
  说明组合损失 + 充分训练让转置卷积的潜力得以发挥，两种上采样最终几乎持平。
- 10 分类的“全类 mIoU”变化不大（受缺席类别拖累），但**“出现类 mIoU”高达 0.71**，
  说明模型对实际出现的数字分割得相当好——此前 0.4 的数字是被严苛的评估口径低估了。
  这印证了补充评估口径的必要性。

优化版用 `python main_seg.py --epochs 50 --suffix _opt` 复现，汇总见 `results/summary_opt.md`；
基线汇总保留在 `results/summary.md`，二者构成消融对照。

## 七、收敛性与框架上限

从训练曲线看，优化版已基本收敛：2 分类末 5 轮 mIoU 几乎不变、train_loss 稳定在 0.16；
10 分类末段仅余极缓慢上升。继续加轮数只能换来边际提升，不会有质变。

进一步分析瓶颈：2 分类的 train 与 test mIoU 都稳定在 0.86，说明限制并非“没练够”，
而是 LeNet-5 骨干较浅、编码器下采样到 16×16 丢失了空间细节——小数字边界只有几个像素，
难以精确分割。这是结构性限制。在不更换骨干（作业要求骨干为 LeNet-5）的前提下，
当前结果已接近该框架的能力上限；若允许换更深骨干或提高输入分辨率，精度还会进一步提升。

## 八、局限与可改进方向

- 合成数据每张仅含单个数字，真实场景常为多目标，可扩展为一图多数字。
- 10 分类标准 mIoU 口径偏严（含大量缺席类别），本项目已补充“仅出现类”口径作为参考。
- 未使用数据增强与超参搜索；骨干为浅层 LeNet-5，换更深骨干会进一步提升精度。
